# LifeLog · 个人生活管理 App — 产品与技术方案

> 版本：v0.3.0（`0.3.0+1`）　｜　文档更新：2026-10-23　｜　状态：已实现；iOS 工程已配置，**尚未经过 iOS 真机验证**
> **重大变更**：由早期的「Web + App 双端 + 电脑自托管后端 + 离线优先同步」方案简化为
> **「单端 Android App + 手机本地存储」**，不再需要后端、登录与多端同步。

---

## 1. 项目概述

LifeLog 是一款自用的**个人生活管理 App**，覆盖财务管理、外语学习、健康管理三大生活场景，
并提供可调用外部大模型的 AI 助手。

| 项目 | 说明 |
|---|---|
| 形态 | **Android + iOS App（Flutter）**，不含 Web；iOS 工程已配置，待 macOS 构建验证 |
| 数据 | **全部存在手机本地 SQLite**，无服务端、无账号体系 |
| 网络 | 仅 AI 对话与识图需要外网；其余模块完全离线可用 |
| 隐私 | 本地 PIN / 指纹解锁；数据不上传任何第三方 |
| 长度目标 | 数据只有手机一份，必须靠**导出/导入加密备份包**兜底 |

## 2. 需求总结

### 2.1 财务管理

- **记账**：收入 / 支出 / 转账（转出 + 转入账户），按分类记账
- **录入方式**：手动录入 + AI 对话记账 + **支付截图识图自动记账**
- **预算**：月度预算（总预算或按分类），进度与超支提示
- **账户三大类**：资产类（现金、储蓄卡、虚拟账户、债权、自定义资产）、投资类（股票、基金、理财、自定义投资）、负债类（信用卡、短期信贷、长期借贷、自定义负债）
- **资产口径**：总资产 = 资产类余额 + 投资类市值；总负债 = 负债类欠款；净资产 = 总资产 − 总负债；投资盈亏 = 投资类市值 − 累计投入本金
- **账单**：周、月、年三个维度的账单与汇总（横滑周期条选择，财务与健康交互一致）
- **图表**：收入 / 支出分类占比饼图，收支趋势图
- **约束**：仅人民币（CNY），**不做多币种**

### 2.2 学习模块

- **范围**：英语为主，内置 **CET-4（4,541 词）/ CET-6（3,991 词）/ 考研英语（5,043 词）/ IT 行业必备词汇（200 词）** 四本词库，另支持自建词库（CSV / TXT / JSON 批量导入）
- **背词**：间隔重复（SRS / 艾宾浩斯）排程，认识 / 模糊 / 不认识三档反馈
- **卡片**：拼写、音标、释义、例句；点喇叭用系统 TTS 朗读（英式 / 美式可选）
- **测验**：看释义拼写 / 听音拼写两种模式，单轮 10 / 20 / 全部（上限 50 题），完成后保存成绩并计入统计
- **统计**：每日学习量、正确率、用时与趋势；测验次数、答题量、正确率与用时

### 2.3 健康模块

- **体重**：每日体重记录（含时间），体脂率（可选）
- **维度**：多部位围度记录（胸围、腰围、臀围、臂围、大腿围、小腿围、颈围等）；「综合」视图用 2×3 卡片平铺六项最新值 + 雷达图，单部位视图用六条折线（选中高亮、其余半透明）
- **运动**：每日运动记录（类型、时长、距离、消耗卡路里、平均心率）
- **对比**：按周 / 月 / 年三个时间维度查看变化趋势（周、月按天，年按月）
- **目标**：目标体重、BMI 计算、达标进度（增强项）

### 2.4 AI 模块

- **对话**：默认名「小朝」（可改名）、多轮会话、会话历史、**SSE 流式输出**、**Markdown 渲染**、用户与助手消息均可复制（气泡按钮或长按复制单条 / 整段对话）
- **输入**：文字 + **按住说话**（连续分段识别，松手直接发送、上滑取消；无语音服务时提示改用键盘）
- **供应商**：DeepSeek（文本模型 + 多模态识图），**由 App 直接调用**
- **生活智能**：自然语言记账、支付截图识图记账、健康 / 学习建议、日周报总结、数据问答
- **工具调用（Function Calling）**：**17 个工具**覆盖财务 / 健康 / 学习 / 综合概览，支持最多 **3 轮串联**，直接读写本地数据库

### 2.5 平台能力

- **本地解锁**：PIN 码 / 指纹（`local_auth`），保护隐私数据
- **备份**：一键导出 / 导入**加密备份包**（自设密码保护）
- **外观**：6 种主题色可切换，即时生效并持久化；跟随系统深色模式
- **离线优先**：除 AI 外的所有功能无需网络
- **不做**：登录注册、多端同步、打卡提醒、Web 端

|---|---|---|

| 10 | 学习范围 | 英语为主 + 内置词库 + 自建导入 |
| 11 | 打卡提醒 | 不做 |
| 12 | 开源计划 | 计划开源到 GitHub；仓库**不含任何真实凭据与个人数据** |
| 13 | 交付节奏 | 先 MVP 再迭代（财务 → 健康 → AI → 学习） |

**为什么是 Flutter 而不是原生 Kotlin**：一套代码即可，后续若要 iOS 可直接复用；
Drift / fl_chart / local_auth 等本地能力生态成熟；且 Dart 的结果化建模适合承载原本 Python 侧的业务逻辑。

## 4. 总体架构

### 4.1 架构形态

```
┌─────────────────────────────── 手机（Android）───────────────────────────────┐
│                                                                              │
│   Flutter App                                                                │
│   ┌──────────────────────────────────────────────────────────────────────┐   │
│   │  UI 层：财务 / 学习 / 健康 / AI 助手                                    │   │
│   ├──────────────────────────────────────────────────────────────────────┤   │
│   │  业务层：记账聚合、SRS 排程、健康对比、本地规则记账解析                     │   │
│   ├──────────────────────────────────────────────────────────────────────┤   │
│   │  数据层：Drift DAO / Repository                                       │   │
│   └──────────────────────────────────────────────────────────────────────┘   │
│                    │                                    │                    │
│                    ▼                                    ▼                    │
│        ┌───────────────────────┐            ┌──────────────────────┐         │
│        │ 本地 SQLite（唯一存储） │            │ Secure Storage        │         │
│        │ 账单/健康/学习/会话     │            │ DeepSeek Key / PIN 哈希│        │
│        └───────────────────────┘            └──────────────────────┘         │
│                    │                                                         │
│                    ▼（仅 AI 需要）                                            │
└────────────────────┼─────────────────────────────────────────────────────────┘
                     │ HTTPS
                     ▼
            ┌──────────────────┐
            │  DeepSeek API     │
            │  文本 + 多模态识图 │
            └──────────────────┘
```

**关键点**：除 AI 模块外，全链路不依赖网络，也不依赖任何自建服务。

### 4.2 本地数据与备份策略

- 所有业务数据存于 SQLite 单文件，通过 Drift 管理表结构与迁移
- **金额一律用整数「分」存储**（`INTEGER`），避免浮点误差，展示时除以 100
- 软删除：保留 `deleted` 时间戳而非物理删除，用于回收站与误删恢复
- **备份包**：把全部业务表序列化为 JSON → AES-256-GCM 加密（密钥由用户备份密码经 PBKDF2 派生）→ 输出单个 `.lifelog` 文件
  - 导出文件名带时间戳，便于多版本留存
  - 导入时校验格式与版本号，支持「全量覆盖」与「合并」两种模式
  - 建议保存到网盘或电脑；App 内提供「上次备份已超过 N 天」的提醒

### 4.3 AI 可用性与离线降级

**前提**：DeepSeek 是云服务，AI 对话与识图**必须依赖外网**；无外网时不可用。

| 场景 | 外网 | AI 对话 | AI 识图 | 其余模块 |
|---|---|---|---|---|
| 正常 | 有 | 可用 | 可用 | 可用 |
| 离线 | 无 | 仅本地规则兜底 | 不可用（进队列） | **完全可用** |

**离线降级链**

| 层级 | 触发条件 | 能做到什么 |
|---|---|---|
| 1 云端（首选） | 有外网 | 对话、识图、Function Calling 全能力 |
| 2 本地规则引擎 | 完全离线 | 内置解析器识别「午饭 30」「打车 15」这类**高频简单记账**，直接落本地库 |
| 3 离线队列 | 任意离线 | AI 请求与截图存入本地 `ai_pending_task`，联网后自动重放并回填 |

- 识图**没有离线方案**（视觉模型无法端侧运行），离线时统一转队列
- 工具调用的结果直接写本地库，不依赖网络

**已实现的重放策略**

- **入队判断**：无外网且本地规则解析不了这句话 → 入队等联网补答；
  本地规则能处理的高频记账直接落库，不占用队列。
  未配置 API Key 时**不入队**（联网也没用），改为提示先去配置
- **截图**：离线时把图片落到应用文档目录并入队，联网后自动识别；
  识别结果标记为「待确认」，**用户确认后才入账**，保持「识图必须人工确认」的原则
- **自动重放时机**：进入 AI 页时、以及任意一条消息成功拿到模型回复时
  （说明网络已恢复）；另外提供手动「重放」按钮
- **失败处理**：遇到网络/凭据类错误立即中止本轮（后续任务必然同样失败，不必逐个重试）；
  失败任务保留在队列中并显示错误原因，可手动重试或放弃
- 任务状态：`pending`（待联网）→ `running` → `done` / `awaiting`（待确认）/ `failed`

## 6. 关键功能设计

### 6.1 支付截图识图记账

DeepSeek 提供原生多模态 API（`deepseek-flash` 支持图片输入，图片按 token 计费，单图最多 384 tokens），
因此**不需要本地 OCR**，App 直接把截图发给模型。

```
1 用户从相册选图 / 分享导入
2 App 压缩后以 base64 直传 DeepSeek 多模态模型
3 模型按结构化 JSON 输出：
     amount / direction / payee / occurred_at / channel / trade_no / category_hint / confidence
4 App 本地做二次校验与分类映射
     · 商户 → 分类 规则库
     · 历史商户记忆（同名商户上次选的分类）
5 展示「记账草稿卡片」→ 用户确认或修改（金额、分类、账户）
6 确认后写入本地 SQLite
```

| 设计点 | 方案 |
|---|---|
| 去重 | 交易单号优先，否则用 `金额+时间+商户` 生成 `fingerprint`，重复截图不重复入账 |
| 兜底 | 置信度低于阈值时提示手填，不强行自动入账 |
| 隐私 | 截图默认不长期留存；识别后可配置立即删除 |
| 离线 | 无外网时截图存本地并进入 `ai_pending_task`，联网后补识别 |
| 成本 | 单图最多 384 tokens，与文本同价，识别结果本地缓存复用 |

### 6.2 间隔重复背词（SRS）

- SM-2 简化版：每条 `review_record` 维护 `ease`、`interval_days`、`repetitions`
- 三档反馈：认识 → 延长间隔；模糊 → 间隔不变；不认识 → 重置
- 每日任务 = 到期复习词 + 定额新词（比例可配置）
- `next_review_at` 建索引，保证队列生成高效

### 6.3 健康多维度对比

- 体重 / 围度 / 运动按时间聚合：**周 / 月视图按天、年视图按月**出趋势（与财务共用 `ViewPeriod`）
- X 轴只在有数据的点上均匀取最多 6 个标签，避免重叠与空白日期；Y 轴宽度按实际标签文本测量
- 体重提供区间变化、最低 / 最高与 BMI（身高在设置中维护）
- 围度用长表结构，便于任意部位自由对比；旧数据里的「大腿 / 小腿」会归一到「大腿围 / 小腿围」

### 6.6 加密备份包（已实现）

**文件结构**（`.lifelog`，二进制）：

| 偏移 | 内容 |
|---|---|
| 0–7 | 魔术字 `LIFELOG1` |
| 8–23 | PBKDF2 盐（16 字节） |
| 24–35 | AES-GCM nonce（12 字节） |
| 36– | 密文 + 16 字节认证标签 |

- 头部这 36 字节同时作为 GCM 的**附加认证数据（AAD）**，改动魔术字、盐或 nonce 都会导致解密失败
- 密钥由备份密码经 **PBKDF2-HMAC-SHA256（10 万次迭代）** 派生，盐与 nonce 每次导出随机生成
- 明文是「表名 → 行列表（列名 → 原始存储值）」的 JSON，逐表 `SELECT *` 导出，
  整数分与毫秒时间戳原样保留，不做二次转换
- 导入有两种模式：**覆盖恢复**（先清空再写入）与**合并导入**（按主键 `INSERT OR REPLACE`），
  全程在单个事务内完成，中途失败整体回滚
- 导入时按表名白名单过滤、列名做标识符校验，避免备份文件携带任意 SQL
- 文件名带时间戳 `lifelog-YYYYMMDD-HHMMSS.lifelog`，导出后走系统分享面板保存到网盘或电脑
- 导入后手动触发一次表更新通知，页面上的流式查询立即刷新，**无需重启 App**
- App 内记录上次备份时间，超过 **7 天**未备份会在「我的」页标红提醒

**两点必须说明的限制**：

1. **备份密码丢失即无法恢复**，App 内已明确提示；
2. **PIN 与 API Key 不在备份包内**（它们存在 Android Keystore / iOS Keychain），换机恢复后需重新设置 —— 这是有意的安全设计。

### 6.8 词库批量导入（已实现）

**支持的格式**

| 格式 | 说明 |
|---|---|
| CSV / TXT | 一行为一个词：`拼写, 音标, 释义, 例句`，`,` `Tab` 或空格分隔 |
| JSON | 数组，或 `{"words": [...]}`；字段兼容 `spelling`/`word`、`phonetic`/`phonetic_uk`、`meanings`/`meaning`、`examples`/`example` |

- 音标列可选：自动识别 `/.../` 或 `[...]` 形式；两列时第二列直接当释义
- 多个释义用 `;` `；` `|` 分隔，多个例句用 `|` 分隔
- 首行若像表头（含 spelling / 拼写 / 释义 等关键词）自动跳过；`#` 开头的行忽略
- 文件内按拼写去重（不区分大小写），导入时再与词库已有单词合并去重

**导入流程**：选目标词库（或新建）→ 粘贴文本或选文件 → **预览**（将导入 N 个、跳过 M 条、跳过原因明细）→ 确认导入。

跳过是显式的：不像英文单词的行、缺拼写的项、重复项都会列在预览里，不会静默丢弃。

### 6.13 内置词库与拼写测验

- **词库资源**：`app/assets/wordlists/` 下四份 JSON（CET-4 / CET-6 / 考研 / IT），结构为 `{name, source, license, words: [[spelling, meaning], ...]}`，共 13,775 词、约 674 KB。
- **播种**：学习页首帧读取资源后调用 `ensureBuiltinWordbooks`，按名称查找词库；不存在则创建，存在则跳过。分块（每 200 行）插入单词并刷新计数，幂等。
- **旧库升级**：老版本只有「CET-4 核心词」50 词，播种时复用该词库并补齐到完整 CET-4，避免重复词库。
- **抽题**：从当前词库随机抽题，单轮上限 50 题；只抽有释义的单词。
- **判定**：答案 `trim + 小写 + 空白折叠` 后比较，忽略大小写与首尾空格。
- **听写降级**：进入测验前用 `flutter_tts.getLanguages` 预检语音引擎；不可用时禁用听音模式并提示改用释义拼写。播放失败时提供「改用释义拼写」。
- **成绩**：完成一轮才写入 `quiz_sessions` 与 `quiz_answers`；中途退出不保存。结果页显示题数、正确数、正确率、用时与错题列表。

### 6.14 回收站

- 所有业务表已统一软删除（`deleted_at`），回收站直接聚合这些墓碑记录。
- 支持 9 类对象：流水、账户、分类、预算、体重、围度、运动、单词、词库。
- **恢复**：写入 `deleted_at = NULL`；恢复词库时按相同删除时间级联恢复其单词。
- **彻底删除**：直接物理删除；删除单词或词库时同步清理 `review_records` 与 `quiz_answers`，避免孤儿数据。

### 6.16 资产计算口径（v0.2.0）

纯函数位于 `app/lib/data/finance_assets.dart`，账户与流水只做快照输入，便于测试：

```
资产类余额 = 初始余额 + 收入 − 支出 + 转入 − 转出
投资类本金 = 初始本金 + 转入 − 转出
投资类市值 = 本金 + 收入 − 支出 + 手动市值调整
负债类欠款 = 初始欠款 − 收入 + 支出 − 转入 + 转出（不小于 0）
总资产 = Σ 资产类余额 + Σ 投资类市值
总负债 = Σ 负债类欠款
净资产 = 总资产 − 总负债
投资盈亏 = Σ 投资类市值 − Σ 投资类本金
```

- 内部转账（储蓄卡买股票）只在账户间移动资金：总资产与净资产不变，投资本金与市值同步增加。
- 手动更新投资市值只改 `market_adjustment`，差额直接进入盈亏并影响净资产。
- 借钱给他人：新建「债权」资产账户，用转账把现金转入 → 资产内部一增一减；利息用收入记账，计入收益。
- 旧版信用卡负数余额按绝对值视为欠款，保证迁移前后净资产不变。

## 11. 附录：术语

| 术语 | 含义 |
|---|---|
| Drift | Flutter 生态的 SQLite ORM，编译期生成类型安全的查询代码 |
| SRS | Spaced Repetition System，间隔重复记忆系统 |
| Function Calling | 大模型调用外部工具/函数的能力，此处用于读写本地数据 |
| AES-256-GCM | 带认证的对称加密算法，用于备份包加密 |
| PBKDF2 | 基于口令的密钥派生函数，用于从备份密码派生加密密钥 |
| Fallback Chain | 降级链，云端 → 本地规则 → 离线队列 的能力回退顺序 |
